## 1. 系统总览

```
console(主播/推流端 SPA) ──┐
                            ├──> @mooc/live-service(浏览器 SDK 三层 hook)
web(学员端 观众 SSR) ──────┘        │
                                    ├─ Socket.IO /ws/live  信令 ──> server RoomRuntime ──> mediasoup worker/router ──> WebRTC Transport/Producer/Consumer
                                    ├─ Socket.IO /ws/chat  聊天 ──> Redis List
第三方应用(仓库外) ── socket ──────┘        │
   └─ hlsStream 事件取 URL ────────────────┤
                                            └─ HLS 旁路：HlsPipeline ──> PlainTransport + ffmpeg 子进程 ──> server/tmp/hls/{roomId}/ ──> Express /hls 静态(免鉴权)
元数据 CRUD：console ──> Express /api/live ──> @mooc/db-shared Live 模型
              web    ──> Next.js API 路由(/api/live/*) ──> 直连 Mongoose（绕过 Express，双通道现状）
```

- 端口：Express/Socket.IO 同 HTTP server `3004`；mediasoup worker RTC 段 **20000–39999**；ffmpeg 收流段 **40000–49000**（两段必须错开，见红线）。
- 关键环境变量：`WEBRTC_TRANSPORT_IP`（对外宣告地址）、`SOCKETIO_HOST`(console) / `NEXT_PUBLIC_SOCKETIO_HOST`(web)。
- 上线网络要求：防火墙放行 UDP 20000–39999（WebRTC）与 40000–49000（ffmpeg 本机回环，仅 127.0.0.1 可不暴露公网）。

## 2. 原实现（git HEAD 基线）

### 2.1 server 三件套

| 文件 | 职责 | 关键问题 |
|---|---|---|
| `server/src/servers/mediasoup/index.ts`（已删） | 模块级 `mediasoupRouters: Map<roomId, Router>` + `weakData: Map<roomId, Map>`（内含 transportsMap/recvTransportsMap/rtpCapabilitiesMap 为 **WeakMap(socket)**、producerMap/consumerMap/plainTransportMap） | worker 未设 rtcMin/MaxPort；`worker.on('died') → process.exit(1)`；SIGINT/SIGTERM 处理器在 `createMediasoupRouter()` 内注册（每次建 router 重复挂）；无房间抽象、无生命周期管理 |
| `server/src/servers/ffmpeg/index.ts`（已删） | 全局 `ffmpegMap(roomId→child)` + `startFFmpeg({onStart,onOpening,onExit})` | **`onStart` 挂在 stderr 第一行**→ plainTransport.connect 时机早于 ffmpeg bind 端口，RTP 全部打丢，10s listen_timeout 后退出（HLS 恒不可用的根因一）；**`onOpening`（stderr 出现 "Opening"）+ existsSync 判就绪**→ 陈旧文件假就绪 418ms（根因二）；`-hls_flags delete_segments+append_list` 且不清目录→ 僵尸进程向旧 playlist 续写、内容循环播放几秒旧片（根因三）；无 SIGTERM/SIGKILL 升级，杀不干净 |
| `server/src/servers/websocket/live.ts`（HEAD 版） | 单函数内联所有事件：`getRtpCapabilities/getReport/transportConnected/produce/getConsumer/closeProducer/getProduces/disconnect` | 无统一 ack 信封，失败路径 `cb({error})` 或直接**不回调**（getConsumer 条件不满足时静默，前端 Promise 永久挂起）；`disconnect` 监听器注册在 `produce` 回调**内部**，重复推流会累积；producer 关闭即全房 close（无按 socket 归属）；无 HLS 状态机、无重启、无指标 |

### 3.2 HLS 旁路（本次迭代的最终形态）

**状态机**：`idle → starting → running → stopping → idle`；所有启停进**同一条串行队列** `enqueue`（防并发重建泄漏 transport）。

**run() 时序**（关键不变式的执行顺序）：
1. `await teardown(false)` —— 上一代进程**确认退出**后继续（单一写者，不变量 1）；
2. 取 router + `pickHlsProducers`（策略：麦克风+screen-* 优先，无共享回退 camera）；
3. `createPlainTransport` → `consumer.resume()`；
4. `new FFmpegProcess` + `start()`（**spawn 前 rmSync+mkdirSync 清空输出目录**）；
5. **`watchPlaylist(process)` —— 就绪唯一入口**（真就绪，不变量 2）；
6. `await bindPortsAndConnect`：`waitForUdpPortBound` 确认 ffmpeg 已 bind SDP 声明端口 → 才 `plainTransport.connect()`（comedia:false 不 connect 永不发流；connect 重试 3×500ms）；
7. 异常：`stop()` 当前进程防僵尸 → 清 transport → `scheduleRestart`（退避 1s/3s/9s，超限停 error 并 give up 日志）。

**watchPlaylist（3.26 方案 A 后）**：`segmentCount()>0`（本代 playlist 出现 `#EXTINF`）→ `markRunning` → `onReadyChange(true)`。20s 未出片**只告警一次**，降频 1s/次**贯穿进程始终继续观察**，直到出片或进程退出/teardown。背景：屏幕共享首片实测 15s～38s+，一次性窗口会永久丢失真就绪信号（3.26 缺陷即源于此）。

**isReady** = `state==='running' && process.isAlive()`；url 仅在 ready 时给出（恒定地址，不变量 3：`/hls/{roomId}/playlist_live.m3u8`，无 `?v`，防缓存交给 HTTP 头）。

**FFmpegProcess**：
- `stop()` async：SIGTERM→等 2s→warn 升级 SIGKILL→最多等 10s；返回即代表已退出。
- stderr 逐行 logger.info：过滤 `frame=` 进度行、相同行 2s 去重、tail 20 随退出信息落日志（`onExit` 携带 code/signal/intentional/logs）。
- 输入选项（必须在 `-i` 前）：`-protocol_whitelist file,udp,rtp,pipe`、`-listen_timeout 30`、`-reorder_queue_size 2000`、`-probesize 50000000`、`-analyzeduration 5000000`、`-f sdp -i pipe:0`（SDP 经 stdin 写入，EPIPE 必须吃掉）。
- 输出：`libx264 + aac`、`-tune zerolatency -preset ultrafast`、两级 scale 取偶（1280:720 decrease → trunc 偶数，修奇数高度崩溃）、`-pix_fmt yuv420p -fps_mode cfr`、`-af aresample=48000:async=1:first_pts=0`（Opus DTX 静音缺口，first_pts=0 防 36s 硬补）、`-hls_time 4 -hls_list_size 15 -hls_flags delete_segments+temp_file+omit_endlist`（**无 append_list**；temp_file 原子落盘；编号每代从 000 重开）。
- **不加** `-use_wallclock_as_timestamps`（对 `-f sdp` 是 no-op）、**不用** `setpts=PTS-STARTPTS`（静音空洞下人为制造偏移）。

**live.ts hlsStream 事件**（第三方契约）：payload `{waitMs?}`（clamp 到 3000/上限 8000）；未 ready 先 `ensureRunning()`；仅"确有 producer 可转码"才 `waitUntilReady`；**始终返回可诊断信封** `{ready, state, url, roomId, retryAfterMs, error?}`，`retryAfterMs` 按状态给（starting/idle 2000、stopping 3000、error 5000）。**调用方是仓库外第三方应用**，console/web 不调用。

### 3.4 前端 SDK（packages/live-service，唯一实现）

- **useMediaStream**（容器层）：三个常驻 `MediaStream`（remote/micro/camera）+ 三个 video/audio ref 的 srcObject 绑定。
- **useMediasoup**（轨道/生产消费层）：`targetMicrophone/targetShareScreen/targetCamera` 开关（screen 拆 screen-video/screen-audio 两个 producer）；`producerControl` **仅视频轨锁 H264+encodings，音频不指定 codec**；`producer.on('@close')`→ emit `closeProducer`；consumersMap/producersMap 管理，`removeConsumer` 只关 client 侧。
- **useSocketIo**（信令编排层）：连接 `io(`${host}/ws/live`, {query:{roomId}})`；时序= connected/liveRoomInfo 监听→ getRtpCapabilities→ `device.load`→ send/recv transport 建立→ newProduce/producerClosed/liveEnded 监听→ **观众且 status==='live' 时 getProduces 自动补消费存量 producer**；`requestWs` Promise 化 + 10s 超时 + 信封解包（非信封向后兼容）；`sendTransport.on('produce')` 走 requestWs 且有 `errcb`（失败不再永久挂起）；`liveEnded`→ removeAllConsumer + close 双 transport + `getDetail()`(web 端 router.refresh)。
- **consumer-id.ts**：localStorage `consumerId` 游客 UUID，供 `recordUser` 统计看过人数。

### 3.5 页面消费与元数据通道

- console：`/live/list`（管理 CRUD）→ `/live/:id` 控制台（`console/index.tsx` 状态机 scheduled/live/ended/paused，`startLive/closeLive` 调 `/api/live` + ref 控制 `components/live.tsx`（推流 UI，消费 live-service）与 `components/chat.tsx`（/ws/chat））。
- web：`(content-page)/live/[id]/page.tsx`（SSR 取 liveInfo + `modules/live/live.tsx` 观众播放 + `chat.tsx`）、`(content-page)/live/center`、`(mobile-page)/m-live/[id]`；元数据走 Next API `web/src/app/api/live/[id]、/center`（直连 Mongoose）。
- server `/api/live`：直播实体 CRUD（@mooc/db-shared `Live` 模型：title/instructor/status/startTime/endTime 等）。

### 3.6 房间生命周期时序（一次完整直播）

```
主播 join → getRtpCapabilities/device.load → getReport(send/recv) → transportConnected(上报 rtpCapabilities)
→ targetShareScreen → sendTransport.produce ×2(screen-video/screen-audio) → server produce
   → RoomRuntime: hasPublished=true, state=live → 广播 newProduce(含自己) → hls.scheduleSync(200ms 防抖)
→ 观众 join → connected→recordUser → 存量 getProduces 补消费 / 增量 newProduce→getConsumer→recvTransport.consume
→ HlsPipeline.run(): teardown→plain×N(先 paused)→ffmpeg spawn→watchPlaylist→bind 确认→connect→resume
   → 出首片 → running → 广播 ffmpegReady；第三方 socket 发 hlsStream → ready:true + 恒定 url → curl /hls/...
主播关共享 → closeProducer/producer '@close' → dropProducer → scheduleSync → run() 无 producer→idle
主播断线/关页 → disconnect → removeSession → hasPublished→closeAllProducers(广播 producerClosed {})
点"结束直播" → closeLive → manager.close → 广播 liveEnded → hls.dispose(teardown(true) 删产物) → router close
```

## 5. 红线（改前必读，均源自线上事故）

1. **两个 UDP 端口段必须错开**：worker `rtcMin/MaxPort(20000-39999)` vs ffmpeg 预留段(40000-49000)；调整任何一侧都要同步防火墙放行段。
2. **绝不用 bind 方式探测 UDP 端口可用性**（`isUdpPortListening` 用 ICMP 不可达 + close 事件等待；历史：探测 socket 泄漏把整段端口占死）。
3. **plainTransport 不显式指定 port**（worker PortManager 抢坑 EADDRINUSE 死循环）；**comedia:false 必须显式 connect**，且 connect 必须在确认 ffmpeg bind 之后。
4. **就绪唯一入口是 watchPlaylist 的 segmentCount**；不得恢复 existsSync/stderr "Opening"/onOpening 假就绪通道；`READY_POLL_TIMEOUT_MS` 到点只告警不终止。
5. **spawn 前必须清目录 + teardown 必须 await stop()**（单一写者）；不得恢复 `append_list`。
6. **播放地址恒定**，防缓存靠 `Cache-Control` 头（m3u8 no-cache / ts no-store），不得加回 `?v=`。
7. **producer 增删一律经 `hls.scheduleSync()`**（防抖 200ms），不要绕过队列直接启停管道。
8. ffmpeg `-analyzeduration` 保持 5000000；音频不设 codec、视频锁 H264；`-use_wallclock_as_timestamps` 与 `setpts=PTS-STARTPTS` 均不要加。
9. `/hls` 与 `/ws/*` 目前**无鉴权**（含任意 roomId 可建房间/取流，已知情、暂按需求不做）。
10. 开发调试：`tsx watch` 改 `server/**` 会热重载清空房间态——复测必须重开屏幕共享；`server/logs/combined.log` 为 UTC（本地 +8）。
